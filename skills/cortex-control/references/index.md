# Report examples

All authored reports are in English and use the same Markdown writer. Preserve
necessary exact quotations in their original language. Every report opens with
the decision brief the result and publication tools require; beyond it these
examples guide useful content, and no further headings, order, status words or
hidden JSON are required. Choose the example for the actual assignment purpose,
even when the profile usually uses another one. The runtime publishes the task
pipeline; workers use these examples for full reports.

| Purpose | Typical profiles | Example |
| --- | --- | --- |
| Mixed work | General, technical writer | [General result](report-example.md) |
| Work breakdown and dependencies | Planner | [Plan](plan-example.md) |
| Research, design or root-cause findings | Explorer, architect, database architect, UX designer, performance engineer, debugger | [Investigation](investigation-example.md) |
| Code, data, infrastructure or remediation | Backend, frontend, fullstack, mobile, data, DevOps, refactorer, accessibility fixer | [Implementation](implementation-example.md) |
| Independent audit, test evidence or review | Build verifier, QA, code reviewer, security auditor, accessibility auditor | [Verification](verification-example.md) |
| Knowledge and guidance changes | Technical writer | [Documentation](documentation-example.md) |

Separate observed checks from proposed checks. Keep full evidence in the report. Give the coordinator a brief preview containing
the result, observed checks, unresolved limits and next action rather than a bare
declaration of success.

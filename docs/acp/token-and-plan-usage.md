# Token and provider plan usage

Cortex records one `usage_records` row for each engine `session/prompt` call, including coordinator continuations, worker turns, retries, and calls that fail after starting. A row is tied to its exact task, attempt, and engine session. The qualified Codex and Claude ACP adapters return **per-turn** `PromptResponse.usage`; Cortex persists the last token report from that call once. Intermediate `usage_update.used/size` is current context occupancy and is never added to a task token total. It can change within a turn and after compaction.

The Pipeline **Task tokens** figure sums reported calls across the task, including the coordinator and every worker attempt. **Coordinator** is the subset whose runtime attempt ID starts with `co_`. A worker card sums reported calls bound to its displayed execution attempt and any audited predecessor route hops for that attempt. These are token counts, not a bill, account quota, or context-window percentage. `totalTokens` is authoritative when present; otherwise the display adds uncached input, output, cache reads, and cache writes. The separate cache figures are already part of the total. Claude and Codex both report cache reads separately from uncached input, so a card can show a small `↑` value beside a large cache-read value.

A call with no recognized token report is **unavailable**, not zero. The UI displays the number of such calls beside known token totals; if every call is unknown, it says **Tokens unavailable**. The observability summary also counts unknown calls separately. It aggregates the full task; its public per-call list remains bounded. Replayed UI events do not create usage records. Repeated real engine prompts, including retries, each create their own record. The installed Claude adapter supplies per-turn `PromptResponse.usage` on a settled prompt, with uncached input, output, cache reads, cache writes and total tokens. If a prompt is interrupted before that response arrives, its partial `usage_update.used/size` still describes context occupancy and cannot be converted into a token total; the call remains explicitly unavailable.

The Paseo plugin displays per-worker context occupancy and token counts on worker cards. It does not display provider subscription-window percentages: Paseo's provider schema exposes context and token-count fields, but no plan-quota field or API for replacing the host's native Context window indicator.

The automated tests verify per-call aggregation, cache-inclusive fallback totals, and unknown-call disclosure. They do not establish rendered Paseo behavior; that requires an isolated real-client observation.

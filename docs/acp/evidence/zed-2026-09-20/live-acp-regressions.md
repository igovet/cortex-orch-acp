The test Zed profile initially prompted for ordinary `Run Command` actions.
Cortex's downstream permission bridge logged automatic approval for ordinary
worker requests; the extra prompt was visible at the Zed client layer. After
setting the documented `agent.tool_permissions` in the **disposable Zed profile**,
the second run did not prompt for its ordinary read/test/edit actions. Deletion
and unclassifiable command behavior under that Zed setting were not exercised,
so the broader “all but deletion” policy is not yet qualified end to end.

The new Zed thread initially displayed Claude in its selector even while the
persisted Cortex default was Codex. Before the second run, Codex Luna was
explicitly selected in Zed, and `attempt_effective_context` confirmed Codex
as the coordinator. The automatic selector/effective-route alignment remains
unverified and must not be inferred from the successful explicit selection.

The attempt-state recovery fix has not been rechecked by a crash/restart live
scenario. The post-gate run qualifies only the pipeline and completion scenario
listed above; it does not establish all real-client cases or qualify source

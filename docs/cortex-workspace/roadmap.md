# Roadmap

**Status: Gate D passed on 2026-11-05: the owner accepted the clickable browser prototype (CW-D02 phases P0 to P6), which is mock-only, unqualified code built on the static mockups. Mobile is deferred, Gate M gates only mobile and Android work, the local desktop slice (M2) is built with its no-paid and container checks, and no milestone is qualified for release.**

On 2026-11-05 the owner agreed the static mockups in `prototypes/cortex-workspace/mockups/` as the design basis and authorised a clickable browser prototype. Gate D is now recorded. The owner also approved a user-level Rust installation. Rust 1.99.1 is installed. Native builds run in a Docker container and need no development packages on the host ([platforms](platforms.md)). One revised Paseo-style direction based on A replaces the earlier three-way selection; round-one concepts and the superseded [desktop direction](design/desktop-direction.md) remain historical mock evidence, not approved designs.

Milestones run in this order. Items inside a milestone may run in parallel where the index dependencies allow. Each lists the [backlog](backlog/index.md) items it contains by ID. The index holds the phase, dependencies and size of every item. The first release is the Ubuntu desktop; Android is qualified separately and follows later, after Gate M; see [platforms](platforms.md).

## Owner decisions (2026-11-05)

- Gate D passed for the clickable prototype; see [desktop approval](design/desktop-approval.md).
- Mobile is deferred. CW-M03 (Gate M) is no longer a direct dependency of any desktop item; it still gates the Android and phone-only items. Desktop implementation does not wait for Gate M.
- Desktop release qualification is separate from mobile. The first release is the Ubuntu desktop, checked and released on its own; Android follows later. CW-Q01, CW-Q02 and CW-Q06 are split into desktop and mobile successors, and no desktop qualification item reaches CW-M03.
- Build order: a local vertical slice first (real Tauri window, Rust machine service and real Cortex), then the screens one by one, then remote machines, relay and push. See M2 to M5.
- Toolchain: a user-level Rust installation is approved. Native builds run in a container, so the owner does not install system development libraries on the host; this replaces the earlier instruction that the owner installs them. The observed versions and prerequisites are in [platforms](platforms.md) and [CW-F01](backlog/CW-F01.md).
- Attachments by drag and drop and paste in the composer and the free-form answer field (CW-R39): carried by backlog items CW-U03, CW-U12, CW-U13 and CW-U14. The local slice does not support attachments and shows them as unavailable.
- Automatic sprint moves a checked task to Ready to merge by itself, with owner confirmation there (CW-R20): carried by CW-U05.
- Check recovery, forced re-run, and acceptance with an unpassed check only for a technical blocker (CW-R40): carried by CW-U04 and CW-C07. Prototype code uses fixtures only and may not silently become production authority.
- Orchestration settings parity with the Cortex configuration in Paseo, editable MCP servers and per-tool access on listed MCP tools (CW-R41): carried by CW-U07 and CW-C01.
- The `.deb` bundles the complete runtime and automatically starts its channel's user service; no source checkout or manual environment file is required. This replaces the earlier manual-service rule. Active-manager and sandbox qualification limits remain explicit in [platforms](platforms.md).
- Desktop self-update from GitHub releases for the `.deb` package (CW-U16) is planned, after the local desktop slice.
- All desktop screens open on real data, ahead of their planned M3 and M4 items: the owner asked for working functionality before reviewing the installed app. The local machine helper ([protocol](protocol.md)) carries Git, files, workers, Cortex settings and owner task records, and the planned items stay Planned until each is qualified. Git here uses the `git` CLI, not the planned `git2-rs`; tasks run in the main checkout, and a sprint's automatic queue moves only while the app is open. Still off, with the reason on the control: the terminal (CW-T01), voice (CW-U11, CW-U15), attachments, remote machines (M5), per-task route and worktree choice, generated titles and merge conflict handling.
- Dev and release channels are isolated (CW-R42). A local build is the dev channel, and manual GitHub Actions runs publish production from `main` and dev prereleases from `dev` (owner decision 2026-11-06). The dev settings clone and the project refusal rule are in [CW-S12](backlog/CW-S12.md); packaging and the release workflow are in [CW-S11](backlog/CW-S11.md).

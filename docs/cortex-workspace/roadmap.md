# Roadmap

**Status: Gate D passed on 2026-11-05 (the owner accepted the clickable browser prototype). The local desktop slice (M2) and most desktop screens and features of M3 and M4 are implemented on real data and checked by no-paid automated checks and container journeys. Not verified live: paid model runs, a real Ubuntu desktop session and GPU, a real microphone and a published GitHub release. Embedded remote access (host, pairing, allowlisted tunnel), the Android app in its phone shell and the relay stack in `deploy/relay/` are built and checked only by no-paid automated tests and one debug APK build; nothing is verified on a physical Android device or emulator, through a relay, or between a real phone and a real desktop. Push, the desktop's own remote machines, Android Keystore key wrapping and app lock are not implemented. No milestone is qualified for release.**

On 2026-11-05 the owner agreed the static mockups in `prototypes/cortex-workspace/mockups/` as the design basis and authorised a clickable browser prototype. Gate D is now recorded. The owner also approved a user-level Rust installation. Rust 1.99.1 is installed. Native builds run in a Docker container and need no development packages on the host ([platforms](platforms.md)). One revised Paseo-style direction based on A replaces the earlier three-way selection; round-one concepts and the superseded [desktop direction](design/desktop-direction.md) remain historical mock evidence, not approved designs.

Milestones run in this order. Items inside a milestone may run in parallel where the index dependencies allow. Each lists the [backlog](backlog/index.md) items it contains by ID. The index holds the phase, dependencies and size of every item. The first release is the Ubuntu desktop; Android is qualified separately and follows later, after Gate M; see [platforms](platforms.md).

The P7 checks other than the owner's acceptance are not recorded as run.
2. **M2 Local desktop vertical slice (Phase 3+; first implementation).** CW-S01 to CW-S12. A real Tauri window, the Rust machine service and the real Cortex runtime carry one owner journey: open a project, activate Cortex, save a description-only draft, start it, watch observed progress, answer a named question and read the runtime result. The slice uses narrow subsets of CW-C02a, CW-C02b, CW-C03, CW-C04, CW-F01, CW-H01, CW-H02 and CW-U01 and does not close them. Progress: CW-S01 to CW-S12 are built, and their no-paid checks pass. The native WebKitGTK journey passes in the container build with fake engines; it is observed through the accessibility tree as text, with no screenshots. Still unverified: the different-OS-user connection (CW-S08), starting and stopping the user unit on a reachable user manager (CW-S11), and the GitHub release run (CW-S11, CW-S12). Exit: the no-paid checks of each slice item pass, and the rendered Ubuntu observation of the journey is recorded or marked blocked with its cause. No paid live check is run without an owner request.
3. **M3 Desktop contracts, platform foundations and services (Phase 3+).** CW-F03 (CodeMirror 6 and xterm.js fixture), CW-F04 (runtime workspace and attempt validation), CW-F05 (WebKitGTK startup mitigation), CW-C01, CW-C02 (roll-up of CW-C02a and CW-C02b), CW-C03, CW-C04, CW-C05, CW-C06, CW-C07, CW-C08, CW-H01, CW-H02, CW-H03, CW-H04, and CW-I01, CW-I02, CW-I03: the full versioned contract, outbox and snapshot cursor, decision handling, typed projections, human-mutation lease, file tree and saves, and crash reconciliation. The local wire contract (version 1.8), the invalidation journal with bounded snapshot reads, decision handling, typed projections, file tree and hash-checked saves, and crash reconciliation exist. Not implemented: the public versioned contract for other clients, the human-mutation lease, create and rename of files, and the CodeMirror merge-and-language-server fixture. See the [backlog](backlog/index.md) for each item.
4. **M4 Desktop screens and desktop features, one by one (Phase 3+).** Screens follow the slice: CW-U01 (board, list and create), CW-U02 (task detail), CW-U03 (decision queue), CW-U04 (result), then CW-U10 (composer and session controls), CW-U13 and CW-U14 (workers and worker messages), CW-U12 (steer and queue), CW-U11 (voice, after CW-U15), CW-U05, CW-U06 and CW-U08 (sprints, archive and controls), CW-U16 (desktop self-update from GitHub releases, with the `.deb` package from CW-F01). Status: implemented on real data for CW-U01 to CW-U06, CW-U08, CW-U10, CW-U12, CW-U13 and CW-U14, CW-C09 to CW-C12, CW-G02, CW-G03, CW-G05a, CW-G07, CW-I04a (in part) and CW-T01. 5. **M5 Remote machines, relay and push (Phase 3+; after local desktop).** CW-H05 (machine registry and connector), CW-U07 (per-machine orchestration settings), CW-U09 (machine switcher), CW-U15 (machine dictation service), CW-N01 (embedded iroh endpoint), CW-N05 (self-hosted relay), CW-P01 (push gateway container), CW-P06 (Docker Compose stack for relay and push gateway). Exit includes the owner's relay access-mode decision, the gateway caller-authentication decision and the owner server inputs (domain name, public IP and ports) recorded in [risks and open decisions](risks-and-open-decisions.md). Mobile qualification items (CW-Q01b to CW-Q06b) are not done.
7. **M7 Desktop release qualification (Phase 3+).** The Ubuntu desktop is qualified and released on its own: CW-Q01a (fake-ACP desktop scenario), CW-Q02a (desktop fault and race matrix), CW-Q03a (rendered Ubuntu accessibility and long-history checks), CW-Q04a (Ubuntu installer, service and authorization checks), CW-Q05 (desktop migration and rollback rehearsal) and CW-Q06a (Ubuntu pilot checklist and qualified-support statement). **Post-v1:** CW-P05, optional UnifiedPush receiver support. It is not part of M1 to M7.

No production backend exists for the remote or mobile paths before Gate M and the M5 exit. The local desktop slice in M2 is the only production implementation path before those gates.

## Owner decisions (2026-11-17)

- The owner approved the static phone mockups in `prototypes/cortex-workspace/mobile/` and decided: the Android client is the same adaptive interface as the desktop (not React Native, not two navigation concepts); Android connects only to remote machines; no tab strip on the phone; larger touch controls on the phone only; read-only Code and no terminal in the first version; app lock optional and off by default. See [mobile approval](design/mobile-approval.md).

## Owner decisions (2026-11-05)

- Gate D passed for the clickable prototype; see [desktop approval](design/desktop-approval.md).
- Mobile follows the desktop. CW-M03 (Gate M) is no longer a direct dependency of any desktop item; it still gates the Android and phone-only items. Desktop implementation does not wait for Gate M.
- Desktop release qualification is separate from mobile. The first release is the Ubuntu desktop, checked and released on its own; Android follows later. CW-Q01, CW-Q02 and CW-Q06 are split into desktop and mobile successors, and no desktop qualification item reaches CW-M03.
- Build order: a local vertical slice first (real Tauri window, Rust machine service and real Cortex), then the screens one by one, then remote machines, relay and push. See M2 to M5.
- Toolchain: a user-level Rust installation is approved. Native builds run in a container, so the owner does not install system development libraries on the host; this replaces the earlier instruction that the owner installs them. The observed versions and prerequisites are in [platforms](platforms.md) and [CW-F01](backlog/CW-F01.md).
- Attachments by drag and drop and paste in the composer and the free-form answer field (CW-R39): carried by backlog items CW-U03, CW-U12, CW-U13 and CW-U14, and implemented; attachments are stored as private files and referenced by digest.
- Sprint run modes Manual, Hybrid and Automatic: Automatic runs a checked task to Done on the current branch by itself, asking the owner only work questions and permission requests, while Hybrid stops at Ready to merge for owner confirmation (CW-R20): carried by CW-U05. Live and rendered Automatic qualification is not run.
- Check recovery, forced re-run, and acceptance with an unpassed check only for a technical blocker (CW-R40): carried by CW-U04 and CW-C07. Prototype code uses fixtures only and may not silently become production authority.
- Orchestration settings parity with the Cortex configuration in Paseo, editable MCP servers and per-tool access on listed MCP tools (CW-R41): carried by CW-U07 and CW-C01.
- The `.deb` bundles the complete runtime and automatically starts its channel's user service; no source checkout or manual environment file is required. This replaces the earlier manual-service rule. Active-manager and sandbox qualification limits remain explicit in [platforms](platforms.md).
- Desktop self-update from GitHub releases for the `.deb` package (CW-U16) is partly implemented: the update page checks SHA-256 and refuses a downgrade, but the package signature is not verified and no release is published.
- All desktop screens open on real data. The local machine service carries Git, files, workers, Cortex settings and owner task records ([protocol](protocol.md)), and the corresponding backlog items state their status individually. Git uses the `git` CLI, not `git2-rs`. A sprint's automatic queue runs in the service, so it moves while the window is closed and the service runs. Task worktrees are not enabled: the service reports them as unavailable and every task runs in the project folder. Terminal, local voice input, attachments, generated titles, and the Ready to merge conflict display are on. Remote machines (M5) and handing a merge conflict to Cortex are not implemented. Voice input is local and Russian-only.
- Dev and release channels are isolated (CW-R42). A local build is the dev channel, and manual GitHub Actions runs publish production from `main` and dev prereleases from `dev` (owner decision 2026-11-06). The dev settings clone and the project refusal rule are in [CW-S12](backlog/CW-S12.md); packaging and the release workflow are in [CW-S11](backlog/CW-S11.md).

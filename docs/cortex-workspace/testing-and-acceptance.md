The packaged owner-scale walkthrough is `python3 -B tests/workspace_support/run_owner_walkthrough.py --package <extracted-dev-package> --evidence <new-evidence-directory>`. It runs in a disposable no-network container with empty HOME, a real release store alongside dev data, long descriptions and questions, six dependent sprint tasks, eight execution workers with long histories, and a real Git conflict. Sixty client-clock minutes are simulated; the host and service clocks are unchanged. It measures idle/hover mutations, geometry, visible ages, owner-action cues and double-submit feedback without screenshots. Add `--clipboard` for physical text dragging and Ctrl+C with native clipboard readback on Home, result prose and Settings. Repeating a command retains earlier observations and allocates a fresh evidence suffix and package-runtime copy. This is measured native-window evidence, not a subjective visual verdict or a real-engine workload.

For the local slice, the no-paid checks use fake engines and the scripted protocol peer. A browser run does not qualify the WebKitGTK window. Native checks run in the container build ([platforms](platforms.md)); a native check that cannot run is recorded as blocked rather than passed. Rendered Ubuntu observations are recorded as structured text outcomes, without screenshots.

A control is shown to work only when a real pointer clicks it. `/usr/bin/python3 -B packaging/container/check_real_input.py [--prefix /usr] [--app <desktop-binary>]` clicks the installed window with X server input (XTEST through xdotool) on a private Xvfb display with a disposable HOME, runtime directory and session bus, and leaves nothing running. AT-SPI is only read, to find a control and to see what the screen shows next; nothing is dispatched into the page. It clicks only once the machine reads Connected, in a fresh home and in a home whose project runtime is away while its saved sprint plan names tasks the runtime has not listed. Checks that drive the page through DOM events, a preloaded probe or accessible actions skip hit-testing, and any check covers only the states its fixtures create, so neither establishes that a person can use the window. A build that is not installed is checked by passing its desktop binary as `--app`, because the service accepts only its installed runtime or a source checkout.

Before any desktop archive is handed to an owner, require the [installed real-input gate](../project/verification.md#installed-desktop-real-input-gate) on that exact archive. It installs through apt in disposable systemd containers, launches the installed desktop entry on private X11 and Wayland screens, uses real OS input and closes its own window. Extracted-binary, browser, preload and accessible-action checks cannot replace it. Keep complete output and the archive-bound result; an incomplete or failed gate blocks handoff.

Record exact version, device, commands, outcome and missing evidence. Do not treat mocked or CLI-only results as rendered/mobile qualification. Paid or live external operations need separate authorization.

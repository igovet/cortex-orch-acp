# IDE and Git

**Status: wider design, partly implemented.** The current local Git/checkout slice and its explicit limits are described in [Local task execution](local-task-execution.md). The desktop editor is built with pinned CodeMirror 6, as described in [editing files](local-task-execution.md#editing-files); its hash-checked save and writer check are built, while language servers, the diff views on CodeMirror, the runtime lease and the wider GPU-terminal design below remain planned. Local project terminals are built with pinned xterm.js 6.0.0 (DOM renderer), fit addon 0.11.0 and portable-pty 0.9.0; Ctrl+J opens the owner shell at the registered project folder, not a task worktree. See [terminal security and limits](security.md#owner-terminal-built-local-linux).

Desktop uses CodeMirror 6 for editor/diff, language servers for diagnostics and completion, and xterm.js for service-owned PTYs with graphics fallback. Android uses a touch-oriented editing workflow; a CodeMirror WebView bridge is a candidate subject to feasibility and input tests. Do not assume Monaco mobile support. Files are bounded and path-checked; save requires current content hash and a runtime-confirmed human mutation lease. Conflicts offer compare/reload/save-as, never silent overwrite. Unsaved buffers survive LSP restarts.

At task creation, choose the current checkout and its currently open branch or a dedicated worktree. Concurrency rules for shared-checkout writers remain open. Every task reaches Ready to merge: the repository Git default branch is the default target, changeable per task or sprint. Separate branches offer owner-confirmed local merge (squash by default) or PR creation. A task already working in its target branch instead offers confirmed closure for recorded content already committed, a task-scoped local commit for known pending files, or explicit closure when attribution is unknown; automatic sprint mode does not bypass confirmation. No merge is implicit in result acceptance. A local-only repository needs no remote for review, commits, squash merging or closure; network/PR controls and push-status wording appear only with a configured remote. App-generated commit text is English even for a task discussed in another language; owner edits are preserved.

Current CLI status, diff and log inspection disables configured clean/smudge/process filters through per-command options, so missing required filter programs do not break reads. No Git configuration is rewritten. Filtered content remains labelled; writes keep normal hooks and filters.

Planned Git split: git2-rs for status/diff/log and index operations, installed Git CLI for commit, branch, fetch, pull and push so configured hooks, signing and credential helpers can work. Validate behavior rather than promising perfect equivalence. Show exact worktree identity and changes before mutation. Dirty branch changes and merge conflicts remain visible; never auto-stash/reset. Confirm remote and branch before push; never force push or auto-retry an ambiguous push. Accepting a result does not commit or push. VS Code is not the base; optional Open in VS Code is a separate action that opens the task’s resolved checkout folder, with a visible unavailable reason. Discovery also checks per-user launcher folders; it does not start an editor to test availability.

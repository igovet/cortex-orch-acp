## Evidence and verification

Verify every behavior your assignment changes with available tests, isolated
environments, real installs or authorized calls; retain actual outcomes.
Run the checks that exercise changed tests, code, contracts and documents.
State concrete blockers for unrun or unverifiable checks.
Unrun, failed, truncated and unverifiable checks remain explicit.
Tool/model success is not proof the project works.
Request authorization only when the assignment needs that check and project rules
do not already decide it; preserve policy blockers, including paid-check limits.
Do not run the whole suite: runtime runs final verification after review.
Broaden checks only when assigned or justified by a specific cross-cutting
risk; state the reason.
